# AGC 上架素材（截图 / 图标）多设备形态要求 · 调研结论

调研日期：2026-10-27（2026-10-28 按「首发只发 PC/2in1」更新结论）· 性质：调研结论（包内设备声明未变；AGC 首发只勾 PC/2in1）
依据：华为开发者联盟官方文档（HarmonyOS NEXT / HarmonyOS 5 及以上口径）+ 本仓库现状
适用对象：天关 1.0.0（`cn.alfadb.tianguan`，versionCode 100）。**首发只发 PC/2in1**（2026-10-28 决定）；包内 `deviceTypes` 仍为 手机 / 平板 / PC/2in1，后续可加设备。

> 说明：官方文档为动态页面，本文引用的是 2026-10-27 读到的内容；AGC 控制台需登录，本文**没有**在真实控制台上逐页点选验证“提交按钮是否被拦截”。凡属推断或未找到官方依据的，均在文中显式标注。

## 0. 结论速览（9 条）

1. **截图按设备形态分别要求**：AGC 应用信息里手机 / 平板 / PC/2in1 / 智慧屏（“大屏”页签）各自一组，规格不同，**不能只传一组覆盖全部形态**（仅“运动手表 + 智能手表”共用“手表”页签）。
2. 官方《素材规范》把每个形态的“应用介绍截图”都标为 **（必传）**；是否真的需要该形态，取决于「支持设备」里有没有勾选它。
3. 规格（NEXT）：手机 3–10 张 1080×1920 / 1920×1080；平板 3–10 张 1280×1920 / 1920×1280；PC/2in1 3–10 张 1920×1080（另有 API 文档写 1920×1280，见 §6 冲突）；智慧屏 **5–8 张 1920×1080 + 2 张必传推荐图**（396×223、414×573）。
4. **平板可走“手机兼容分发”**：官方明确“设备类型包含手机时，即便包里未声明平板，也会默认以兼容方式分发到 HarmonyOS NEXT 平板”。所以不勾平板 ≠ 平板用户看不到；但勾了平板就必须配平板素材。
5. **智慧屏没有兼容分发捷径**：不勾选就没有 TV 分发；勾选则必须补 5–8 张 TV 截图、2 张推荐图、1024 图标，并满足横屏 / 遥控器 / 深色模式等适配要求。
6. 官方**没有**“某形态没截图仍可提交”的说明；按“必传 + 按设备页签 + 提交前完成所有应用信息”推断，缺素材属信息不完整，风险是提交被拦或审核驳回——具体拦截点需向华为确认。
7. 图标：手机 / 平板 / PC 接受 216×216 或 1024×1024，智慧屏**只接受 1024×1024**；同一张 1024 正方形 PNG 可在各形态页签复用，不必分别设计。
8. 首发素材现状：PC 5 张 1920×1080（合格，其中 `pc-01-main` 是旧布局、`pc-04-about` 版本号 0.0.1，两张待重拍）；手机 3 张留作参考、平板 0 张，首发都不需要；智慧屏不勾选，不需要 TV 素材。
9. **本项目决定（2026-10-28）**：AGC 支持设备**首发只勾 PC/2in1**（不勾手机、平板、智慧屏），包内 `deviceTypes` 保持 `['phone','tablet','2in1']`（包内范围 ≥ 勾选范围，便于以后加设备与侧载调试）。**因此首发只需 PC 一组截图（3–10 张 1920×1080）**；手机、平板素材都不再是上架必需，等以后加设备时再补；TV 素材本就不需要。

### 0.1 三个直接回答

**a) 智慧屏 / 平板截图是否必填？**

- **勾选就必填，不勾选就不需要**：官方《素材规范》把每个形态的截图都标为“（必传）”，应用信息按设备页签分别配置。
- **平板**：不勾选平板时，手机勾选会自动把应用“以兼容方式分发到 HarmonyOS NEXT 平板”，因此不需要平板截图；勾选平板才需要 3–10 张 1280×1920 / 1920×1280。
- **智慧屏**：没有兼容分发路径；不勾选就不分发到 TV，也就不需要 TV 素材；勾选则必须 5–8 张 1920×1080 + 2 张必传推荐图。

**b) 没有对应真机时，官方接受同形态替代截图吗？**

- **不接受**（未找到任何允许条文；且平板 3:2、手机 9:16、PC 16:9 规格不同，审核指南 1.9 明确禁止拉伸 / 压缩 / 显示不完整）。
- 官方支持的替代做法是**只为部分设备提交**：在「支持设备」里只勾选有素材的形态（例如只勾手机 + PC/2in1）。平板靠“手机兼容分发”仍能覆盖；智慧屏不勾选即不覆盖。
- 注意：应用一旦发布，升级版本**只能增加设备、不能删除**，所以现在不勾的形态以后仍可加；现在勾了但要撤，发布后就撤不掉。

**c) 智慧屏应用必须做遥控器焦点导航，否则会被驳回吗？**

- **未找到**“不做焦点导航就必然驳回”的官方明文。
- 但遥控器可用性是事实上的必需能力：官方焦点规范要求“焦点需要能够遍历所有可获得焦点的界面元素”；智慧屏 UX 标准把“指向热区 ≥2.5cm”“悬停反馈”列为**必须**；审核指南 3.1 要求“适配华为主流终端设备”，UX 不合规是官方列出的常见驳回原因。
- 结论：**至少保证遥控器能完成全流程（焦点或指向）**，建议两者都做；只支持触控 / 鼠标的 TV 应用风险很高。是否“没有焦点导航就一定驳回”**需向华为确认**。

## 1. 官方规则：截图确实按设备形态分别要求

### 1.1 上传界面就是按形态分页签

官方《配置本地化基础信息（介绍、特性、素材）》原文：

> “上传应用介绍截图、介绍视频和推荐视频。**如果应用支持多种设备，需要选择不同设备的页签进行配置**……智慧屏设备素材请在“大屏”页签上传。”

《配置本地化基础信息（应用名称、图标）》对图标也写了同一句话。也就是说：**应用信息不是一个“通用素材池”，而是每个形态一套**。

### 1.2 《素材规范》逐形态列出“（必传）”

官方《素材规范》（HarmonyOS 应用）对每个形态都写：

- 手机：`（必传）应用图标`、`（必传）应用介绍截图`
- 平板：`（必传）应用图标`、`（必传）应用介绍截图`
- PC/2in1：`（必传）应用图标`、`（必传）应用介绍截图`
- 智慧屏：`（必传）应用图标`、`（必传）应用介绍截图`、`（必传）推荐图片`（4 张中前 2 张必传）
- 手表：`（必传）应用图标`、`（必传）应用介绍截图`（4–8 张 840×840）

所以“必填”的判断标准是：**该形态在「支持设备」中被勾选 → 该形态的图标与截图必传**；没勾选 → 不需要该形态的素材。

### 1.3 形态之间不能共用同一组截图

| 形态 | 截图分辨率 | 与其它形态能否共用 |
| --- | --- | --- |
| 手机 | 竖 1080×1920 / 横 1920×1080 | 不能给平板（比例 3:2 不同） |
| 平板 | 竖 1280×1920 / 横 1920×1280 | 不能给手机（9:16 不同）、不能给 PC（16:9 不同） |
| PC/2in1 | 1920×1080（16:9） | 分辨率与智慧屏相同，但内容必须是 PC 实际界面 |
| 智慧屏 | 1920×1080（16:9） | 分辨率与 PC 相同，但张数要求不同（5–8），且内容必须是 TV 实际界面 |
| 手表 | 840×840 | 运动手表与智能手表共用“手表”页签 |

补充一条审核硬规则（《华为应用市场审核指南》1.9）：

> “应用截图需至少上传 3 张不同内容的图片，不得出现重复、模糊、拉伸、压缩、显示不完整、无法体现实际内容等情况。”

因此“把手机竖图拉伸成平板 3:2”“把 PC 截图裁成 1280×1920”都不合规。

## 2. 逐形态规格（HarmonyOS NEXT 口径）

数据来源：官方《素材规范》（页面更新时间 2026-10-13）。大小限制：手机 / 平板 / PC 单张 ≤5MB；智慧屏 ≤2MB。

| 形态 | 张数 | 分辨率（宽×高） | 比例 | 格式 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 手机 | 3–10 | 竖 1080×1920；横 1920×1080 | 9:16 / 16:9 | PNG/JPG/JPEG；WEBP（≤200KB） | 横向 / 竖向分别列出，实际按页面选一个方向上传（未找到“可同时传两组”的官方说明）；**同一形态下介绍视频方向须与截图一致** |
| 平板 | 3–10 | 竖 1280×1920；横 1920×1280 | 2:3 / 3:2 | PNG/JPG/JPEG；WEBP（≤200KB） | 同上 |
| PC/2in1 | 3–10 | 1920×1080 | 16:9 | **PNG/JPG/JPEG（不支持 WEBP）** | 见 §6 与 API 文档的 1920×1280 冲突 |
| 智慧屏 | **5–8** | 1920×1080 | 16:9 | PNG/JPG/JPEG；WEBP（≤100KB） | 另见下方“推荐图片” |
| 手表（参考） | 4–8 | 840×840 | 1:1 | PNG/JPG/JPEG；WEBP（≤100KB） | 本项目不上手表 |

智慧屏“推荐图片”4 张（TV 详情页专用版位，顺序固定）：

| 序 | 分辨率 | 必填 | 用途 / 约束 |
| --- | --- | --- | --- |
| 1 | 396×223 | **必传** | 推荐位小图 |
| 2 | 414×573 | **必传** | 推荐位竖图 |
| 3 | 1920×1080 | 可选 | 详情页背景图：主体在右、左侧不要放影响文字阅读的元素、**图片不能含文字** |
| 4 | 880×494 | 可选 | 推荐位图 |

> 以上“智慧屏推荐图片”是 TV 专属元数据；手机 / 平板 / PC 都没有这一栏。

### 图标规格

| 形态 | 分辨率 | 格式 / 大小 | 备注 |
| --- | --- | --- | --- |
| 手机 | 216×216 或 1024×1024 | PNG ≤3MB；WEBP ≤100KB | 正方形，须与安装后图标一致 |
| 平板 | 216×216 或 1024×1024 | 同上 | 同上 |
| PC/2in1 | 216×216 或 1024×1024 | **仅 PNG** ≤3MB | 同上 |
| 智慧屏 | **仅 1024×1024** | PNG/JPG/JPEG ≤3MB；WEBP ≤100KB | 无 216 档 |

结论：**一张 1024×1024 正方形 PNG 可以同时满足四种形态**；216 档只能用于手机 / 平板 / PC。图标必须与软件包内图标一致（审核指南 1.6 / 1.20，《配置本地化基础信息（应用名称、图标）》原文要求“应用图标必须与软件包中的应用图标一致”）。

## 3. 缺某形态截图能不能提交？

### 3.1 官方能查到的部分

- 《素材规范》把各形态截图标为“（必传）”；
- 应用信息按设备页签分别配置；
- 《提交审核》的流程前提是“完成所有应用信息和版本信息的配置后”；
- 《配置支持设备》要求：包内 `deviceTypes` 范围 **必须大于等于** AGC 最终勾选的支持设备范围。

### 3.2 官方没有写明的部分

**未找到**任何官方文档说明“勾选了某形态但该形态截图为空时，提交按钮会报错 / 还是能提交后被审核驳回”。因此：

- 保守结论：这属于**应用信息不完整**，不应带着缺失素材提交；
- 具体拦截位置（页面红字、保存失败、提交报错、审核驳回）**未找到官方依据，需向华为确认**；提交前以 AGC 页面实际提示为准。

### 3.3 会不会影响分发？

会，分两层：

1. **包内能力**：`module.json5` 的 `deviceTypes` 不含某形态时，该形态用户装了也用不了；官方要求包声明范围 ≥ AGC 勾选范围。
2. **商店素材**：某形态详情页没有截图，属于应用信息不完整；审核 Checklist 明确检查“应用截图和视频是否与应用实际情况相符”，信息不完整 / 与实际不符都是驳回关注点。

## 4. 智慧屏的额外要求（比其它形态多）

官方依据：《智慧屏应用开发》《智慧屏（针对多设备设计）》《焦点导航》《通用应用 UX 体验标准》《智慧屏应用 UX 体验标准》《素材规范》。

| # | 要求 | 官方原文 / 依据 | 性质 |
| --- | --- | --- | --- |
| 1 | **只支持横屏**，屏幕不可旋转（Mate TV 为 3840×2160 px / 1280×720 vp，横屏 LANDSCAPE） | 智慧屏应用开发·屏幕规格 | 硬件事实，竖屏 UI 不可用 |
| 2 | **遥控器是默认输入**：灵犀指向遥控（光标指向、悬浮、点击、滑动）+ 走焦类遥控器（方向键焦点导航） | 智慧屏应用开发；智慧屏设计指南“使用方式” | 必须保证遥控器能完成全部操作 |
| 3 | **焦点可遍历**：焦点要能到达所有可获焦元素，保证功能完整性；页面默认显示焦点 | 焦点导航 | 设计规范（未写成“否则驳回”） |
| 4 | **指向热区**：智慧屏光标指向交互热区 ≥4cm（推荐），**不得小于 2.5cm（必须）** | 通用应用 UX 体验标准 2.1.3.3 | 必须 |
| 5 | **悬停反馈**：所有可交互控件需对指向遥控器光标的悬停状态给出视觉反馈 | 智慧屏应用 UX 体验标准 6.4 | **必须** |
| 6 | **安全边距**：左右 56vp、上下 22vp | 智慧屏应用 UX 体验标准 6.1 | 必须 |
| 7 | **仅深色模式**：智慧屏上 ArkUI 默认深色样式，未适配会出现白底白字 | 智慧屏应用开发·界面布局 | 事实性适配要求 |
| 8 | **无浏览器**：打开协议/隐私政策不能用浏览器，需用 Webview | 智慧屏应用开发·界面布局 | 适配要求（本项目为应用内 rawfile 展示，天然满足） |
| 9 | **TV 专属元数据**：1024 图标 + 5–8 张 1920×1080 截图 + 2 张必传推荐图（396×223、414×573） | 素材规范 | 必传 |
| 10 | **操作设备可选“遥控器”**：AGC 配置支持设备时，智慧屏设备支持选择遥控器作为操作设备 | 配置支持设备 | 建议勾选，声明支持遥控器 |
| 11 | **广电检测（旧口径）**：旧版发布文档写“发布到中国大陆的大屏应用需要通过华为应用市场审核和国家广电总局检测” | 旧版《发布应用（APK）》 | **NEXT 文档未找到对应条目**，见 §8 第 5 条 |
| 12 | **审核更慢**：大屏应用审核可能更长 | 同上 | 预期管理 |

### 4.1 关于“必须做遥控器焦点导航，否则驳回”

**未找到**一条明文写“智慧屏应用不做焦点导航就会被驳回”。但可以确定的是：

- 智慧屏存在**走焦类遥控器**，官方焦点规范要求“焦点需要能够遍历所有可获得焦点的界面元素，以保证功能的完整性”；
- 智慧屏 UX 标准把“指向热区 ≥2.5cm”“悬停反馈”列为**必须**；
- 审核指南 3.1 要求“适配华为主流终端设备”，UX 不符合规范是官方列出的常见驳回原因之一。

因此实务判断：**遥控器可用性（焦点或指向，至少一种能完成全流程）是事实上的必需能力**；只做触控 / 鼠标、遥控器点不动，被驳回或 UX 不达标的风险很高。但“焦点导航”本身没有独立驳回条款，这一点**需向华为确认**。

| PC/2in1 | `pc-01-main` 与 `pc-04-about` 重拍；确认分辨率口径 | 不能跨形态 | 首发唯一需要的一组；若页面要求 1920×1280，需按 3:2 重拍整窗 |
| 平板 | 3 张 1280×1920 或 1920×1280（首发不交） | **不能**：手机 9:16、PC 16:9 都不符 3:2，拉伸违规 | 以后加平板时补拍（见 §7 路径 A） |

| 图标 | 无 | 1024 可全用 | 216 只够手机 / 平板 / PC |

## 7. 可行路径（按成本从低到高）

### 路径 A（已采纳，2026-10-28 更新）：只勾 PC/2in1

依据（官方原文）：

> “当设备类型包含手机时，即便包里未声明平板，应用也会默认以兼容的方式分发到 HarmonyOS NEXT 平板。若您已在包中声明了平板设备，请直接在“支持设备”栏勾选“平板”。”

> “在应用提交上架前，您可随时修改设备……但是应用一旦发布，升级版本只支持增加设备，无法删除已选择的设备。”

做法：

- AGC「支持设备」**只勾 PC/2in1**，不勾手机、平板、智慧屏；
- 包内 `deviceTypes` **保持** `['phone','tablet','2in1']`（包内范围 ≥ 勾选范围，三项合法，也便于侧载调试），不改包、不重建；
- 截图只需 PC/2in1 一组：保留 5 张，重拍 `pc-01-main`（顶部对齐后）与 `pc-04-about`（1.0.0）；
- 手机 3 张与平板 3 张都不交；以后决定加设备（加手机要先办软著；加平板要补 3 张 3:2 截图）时再补素材、发新版本「增加设备」。

代价：手机/平板用户本期拿不到应用；发布后只能加设备、不能删设备；PC 的 UX 门槛成为唯一门槛。

### 路径 B：全量四形态首发（本次不采用）

需要一次性补齐：

- 平板真机（或至少能跑平板分辨率的设备）+ 3–10 张 1920×1280 / 1280×1920 截图；
- 智慧屏真机 + 5–8 张 1920×1080 截图 + 2 张必传推荐图（396×223、414×573；另 2 张可选：1920×1080 背景图、880×494）；
- TV 遥控器全流程验证（焦点 / 指向 / 返回 / 弹窗可关闭）、深色模式核对、热区 ≥2.5cm；
- 可能还需要广电 / 视听备案（见 §8）。

代价：最高，且没有真机时无法满足“截图必须真实来自设备”的审核一致性要求。本次用户决定不上智慧屏，故不采用。

### 路径 C：只勾手机

不推荐：PC/2in1 是本项目主场景，且官方写明“手机和平板应用经过测试后会默认发布到 PC/2in1”，只勾手机反而与产品定位不符。

## 9. 上架自检 / 合法性检测对截图有没有校验？

**结论：都没有。截图只由“应用信息表单 + 人工审核”把关。**

| 检测 | 对象 | 检测内容 | 是否管截图 |
| --- | --- | --- | --- |
| 合法性检测（上传软件包时自动） | 软件包 | 鸿蒙生态规范：包名、签名、版本、API Level、设备类型、权限等；结果分“已达标 / 待优化 / 不通过”，不通过不允许发布 | **否**（官方列的是包级检查项） |
| 上架自检（手动启动，约 1 天） | 软件包在真机上的表现 | 兼容性、稳定性、性能、功耗、UX、隐私；不通过“不影响提交上架申请，但存在被审核驳回的风险” | **否** |
| 应用信息表单 | 图标 / 截图 / 视频 | 分辨率、比例、张数、格式、大小 | **是**（上传页按规范校验，具体提示以页面为准） |
| 人工审核 | 应用信息 + 包 | 审核指南 1.9（≥3 张不同内容、不重复 / 模糊 / 拉伸 / 压缩 / 不完整）、1.20（与安装后名称 / 图标 / 版本 / 内容一致） | **是** |

因此：“合法性和上架自检都过了”**不等于**截图没问题；截图问题只会在人工审核阶段暴露（或表单直接拦）。
